## 1. はじめに（必ずお読みください）

GreatestTrader は、次の 2 つの戦略を組み合わせて **月利 5%** を目指す FX 自動売買システムです。

| 戦略 | 内容 |
|---|---|
| Night Reversion | 日本時間の早朝（NY 17:00〜19:00）に、14 通貨ペアで行き過ぎた値動きの戻りを取る |
| Euro Session | 欧州の午前中に EURUSD を売る |

リスクの取り方は**プリセット**で選びます（6.2 節）。

| プリセット | 向いている人 | 過去検証（2007〜2022 年）月利（複利換算）／最大 DD／最悪月 ※1 | 1 万ドルから 15 年運用した場合の月利（20 ロット上限込み）※2 |
|---|---|---|---|
| **stable5（既定・推奨）** | 月利 5% を目指したい | 5.38% ／ −11.6% ／ −4.75% | 3.07% |
| stable4 | DD を抑えつつ、想定外の急変動にも備えたい | 4.37% ／ −10.7% ／ −3.67% | 2.93% |
| safe2 | 毎月の損失を −2% 前後に抑えたい | 2.00% ／ −11.7% ／ −2.00% | 2.00% |
| classic_* | v1.0 と同じリスク設定（保護機能なし。年末年始の新規停止のみ有効） | 2.58〜6.42% ／ −18〜−33% ／ −8.7〜−14.9% | — |

※1 1 注文のロット上限が効かない、口座が小さいうち（約 6.6 万ドル＝約 1,000 万円まで）の成績です。
※2 v1.2 では、深夜の薄い流動性で注文が市場を動かさないよう、1 注文 20 ロットの上限を既定にしました。口座が大きくなると利益は % ではなく金額でほぼ一定になるため、15 年間の通算ではこの値になります（[06_長期運用評価報告書.md](06_長期運用評価報告書.md) 6 章）。

本書の手順は、次の順に進めてください。

```
① MT5 ストラテジーテスターで、ご自身のブローカーのデータを使って検証（4章）
② Python 版を導入し、check コマンドで接続を確認（5〜7章）
③ デモ口座で 2〜4 週間、ドライランと実発注を試す
④ 少額の本番口座で、選んだプリセットのリスクを半分にして開始（9.3 節）
⑤ 実際のコストが想定どおりか確認しながら、プリセットの値まで戻す
```

> **重要**
> - **月利 5%・最大 DD 20% 以内・最悪月 −2% の 3 つを同時に満たすプリセットはありません。** stable5 は月利 5% と DD を満たしますが、最悪月は −4.75% で、−2% を下回る月が年に 1〜2 回あります。safe2 は最悪月 −2% を満たしますが、月利は 2% 程度です（[05_安定化改修報告書.md](05_安定化改修報告書.md)）。
> - 成績は**取引コスト（スプレッド＋手数料）**で大きく変わります。コストが 0.5 pips 高いと、stable5 の月利は 5.38% → 3.50% に下がります。コストが高い口座では目標に届きません（3章）。
> - stable5 には**マイナスの年（2012 年 −8.4%）と、ほぼ横ばいの年（2013・2014 年）**がありました。最高値を回復するまで 1,176 日かかった期間もあります。長期の模擬運用では、10 年のうちに損失の年が 1 回以上ある確率は 40〜84% です（[06_長期運用評価報告書.md](06_長期運用評価報告書.md)）。
> - 投資は自己責任です。生活資金では運用しないでください。

## 2. 動作環境

| 項目 | 要件 |
|---|---|
| OS | Windows 10 / 11（64 ビット）、または Windows Server（VPS） |
| MT5 | MetaTrader 5（ブローカー配布版）。ビルド 3000 以降を推奨 |
| Python | **Python 3.13（64 ビット）**。python.org から「py launcher」付きでインストール（`setup_windows.bat` がテスト済みの版のパッケージを入れます） |
| 口座 | **ヘッジング口座**（同じ通貨ペアのポジションを別々に持てる口座）。ネッティング口座では起動しません |
| メモリ | 4 GB 以上（バックテストを行う場合は 8 GB 以上を推奨） |
| 回線 | 常時接続。24 時間稼働のため **VPS を推奨**（ブローカーのサーバーに近いロンドンや NY の VPS が理想） |

※ MetaTrader5 Python パッケージは Windows 専用です。Mac / Linux では MT5 の EA 版を使うか、Windows の VPS を利用してください。

## 3. ブローカー・口座の選び方

成績を最も大きく左右するのは**取引コスト**です。次の条件をすべて満たす口座を選んでください。

| 条件 | 理由 | 確認方法 |
|---|---|---|
| ① ECN / RAW / ゼロスプレッド口座（低スプレッド＋手数料型） | 往復コストが 0.5 pips 増えるだけで、複利換算の月利は約 3.5〜4 割（2007〜2022 年）、直近の 2017〜2022 年では約 5〜6 割（v1.0 の設定では 6〜8 割）下がる | 往復コストの目安：EURUSD 1.0 pips 以下、クロス円 2 pips 以下 |
| ② 日本時間の早朝（日付変更直後）もスプレッドが極端に広がらない | 取引する時間帯そのものだから | MT5 でマーケット時間 00:15〜02:00 のスプレッドを数日確認する |
| ③ サーバー時間（どの形式でも可） | 既定の自動判定（auto）が稼働中ずっと確認する。GMT+2（冬）/ GMT+3（夏）の業者が最も多い | `1_check.bat` の表示、または気配値表示の時刻 |
| ④ 14 通貨ペアがすべて取引できる | 分散効果のため | 気配値表示 → 銘柄 |
| ⑤ 最小ロット 0.01 | 少額でも正確なロット計算ができる | 銘柄の仕様 |
| ⑥ 十分なレバレッジ | 下表参照 | 口座の仕様 |
| ⑦ ヘッジング口座 | 1 つの通貨ペアで戦略ごとにポジションを持ち、チケット番号で決済するため | 口座の種類（MT5 の [ツールボックス] → [取引] の表示や、ブローカーの説明） |

### レバレッジと証拠金の目安

同時に保有するポジションの合計建玉（想定元本）は、過去検証（2007〜2022 年）で口座資産の次の倍率でした（新規エントリー時点の値）。

| プリセット | 合計建玉（中央値） | 合計建玉（上位 5%） | 最大 |
|---|---|---|---|
| stable5 | 資産の約 3 倍 | 約 23 倍 | **約 67 倍** |
| stable4 | 約 3 倍 | 約 19 倍 | 約 46 倍 |
| safe2 | 約 2 倍 | 約 10 倍 | 約 18 倍 |
| classic_conservative（0.5%） | 約 4 倍 | 約 15 倍 | 約 30 倍 |
| classic_standard（1.0%） | 約 6 倍 | 約 26 倍 | 約 58 倍 |
| classic_aggressive（1.5%） | 約 8 倍 | 約 36 倍 | 約 87 倍 |

- **国内業者（最大 25 倍）**の場合は、**safe2** を使ってください。stable5・stable4 では証拠金不足で見送られる取引が出ます。証拠金が足りないときは自動的に見送るので安全ですが、その分だけ成績は検証値より下がります。
- 海外業者で stable5 を使う場合は、**100 倍以上**のレバレッジが必要です。
- 上の表は口座が小さいうちの値です。1 注文 20 ロットの上限が効く大きな口座（約 20 万ドル以上）では、25 倍の口座でも証拠金はほとんど不足しません（[06_長期運用評価報告書.md](06_長期運用評価報告書.md) 6.3 節）。

## 4. MT5 ストラテジーテスターでの検証手順（MQL5 版）

ご自身のブローカーの**最新データ・実際のスプレッド**で検証できます。本番運用の前に必ず実施してください。

### 4.1 EA のインストール

1. MT5 を起動し、メニュー **[ファイル] → [データフォルダを開く]** を選びます。
2. 開いたフォルダの `MQL5\Experts\` に `mql5/Experts/GreatestTrader.mq5` をコピーします。
3. 同じデータフォルダの `MQL5\Presets\` に `mql5/Presets/*.set` をコピーします。
4. MT5 で **[ツール] → [MetaQuotes Language Editor]**（F4）を開き、`GreatestTrader.mq5` を開いて **[コンパイル]**（F7）を押します。「0 errors」と表示されれば完了です。
5. MT5 のナビゲーターで「エキスパートアドバイザ」を右クリックし、[更新] を選ぶと `GreatestTrader` が表示されます。

### 4.2 シンボルの準備

1. [表示] → [気配値表示]（Ctrl+M）を開き、右クリック → [銘柄] で 14 通貨ペアと EURUSD を表示状態にします。
2. シンボル名に接尾辞がある場合（例：`EURUSD.raw`）は、EA の入力 **InpSymbolSuffix** に `.raw` を設定します。

### 4.3 テストの実行

1. [表示] → [ストラテジーテスター]（Ctrl+R）を開きます。
2. 次のとおり設定します。

| 項目 | 設定 |
|---|---|
| エキスパート | GreatestTrader |
| 銘柄 | EURUSD（どれでも可。EA がすべてのペアを売買します） |
| 時間足 | **M15** |
| 期間 | 例：直近 3〜5 年（データが長いほど時間がかかります） |
| モデル | まずは「1 分足 OHLC」で全体を確認し、最後に「**リアルティックに基づいたすべてのティック**」で最終確認 |
| 入金 | 例：10000 USD または 1000000 JPY |
| レバレッジ | 実際に使う口座と同じ値 |
| 最適化 | 無効 |

3. [パラメータ] タブで右クリック → [読み込み] を選び、使うプリセットの .set ファイル（`GreatestTrader_Stable5_Default.set`、`GreatestTrader_Stable4_Robust.set`、`GreatestTrader_Safe2_WorstMonth2pct.set` など）を読み込みます。読み込まない場合は、EA の既定値（stable5 と同じ）で動きます。
4. ECN 口座の場合は、**InpCommissionPerLot**（1 ロット往復の手数料、口座通貨）を設定します。例：USD 口座で片道 3.5 ドルなら 7.0。
5. サーバー時間の設定 **InpServerTime** は既定で **AUTO**（稼働中に自動判定）ですが、ストラテジーテスターでは時計を確認できないため NY7（GMT+2 冬／GMT+3 夏）として動きます。テストするブローカーのサーバー時間が固定の GMT オフセットの場合は、テスターでは **Fixed** と **InpServerGMTOffset** を設定してください。
6. [開始] を押します。初回は各通貨ペアの履歴データのダウンロードに時間がかかります。

### 4.4 結果の確認ポイント

| 確認項目 | 目安 |
|---|---|
| [操作履歴] タブの `[GT] started: 14 NR symbols` | 14 になっていること。少ない場合は「symbol not available」のログを確認し、接尾辞を設定する |
| 取引回数 | 14 ペアすべてが取引できる場合、月平均で stable5・stable4 は約 80 回、safe2 は約 65 回。多くの月は 20〜110 回程度（年末年始の停止がある 12 月・1 月や、月次ハードストップが働いた月は少なくなる）。ブローカーのスプレッドによっても変わる |
| プロフィットファクター | 1.2 以上が目安 |
| 最大ドローダウン | プリセットの想定（含み損益込みで stable5 約 12%、stable4 約 11%、safe2 約 12%。v1.0 の classic は conservative 約 18%、standard 約 26%、aggressive 約 33%） |
| 最悪月 | stable5 約 −5%、stable4 約 −4%、safe2 約 −2% |

> 取引回数が極端に少ない場合は、深夜のスプレッドが広すぎて、コストフィルター（InpATRCostMult）で見送られています。その口座ではこの戦略は向いていません。

### 4.5 MT5 で EA をそのまま稼働させる場合

EA はライブ口座でも動作します（Python 版を使わない運用）。

1. 任意のチャート（例：EURUSD M15）に EA をドラッグします。
2. [共通] タブで「アルゴリズム取引を許可」にチェックを入れます。
3. ツールバーの [アルゴリズム取引] ボタンを ON にします。
4. **Python 版と EA を同じ口座で同時に動かさないでください**（二重発注になります）。EA を 2 つのチャートに付けた場合は、2 つ目が起動を拒否します。
5. 通知を受け取るには、MT5 の [ツール] → [オプション] → [通知] で MetaQuotes ID を設定し、**InpPushNotify = true** にします。日次サマリー・DD 警告・停止などがスマートフォンに届きます。
6. InpServerTime は AUTO のままにしてください。PC（VPS）の時計を正確に保つ必要があります（Windows の「時刻を自動的に設定する」を ON）。
7. 最大 DD 停止（stable5 では 20%）を解除するときは、原因を確認してから **InpResetHalt = true** にして EA を設定し直します（停止だけを解除し、最高資産を現在の資産に合わせます）。解除後は false に戻してください。
8. 入金・出金は自動で処理されます（保護機能の基準を同じ比率で調整します）。

## 5. Python 本稼働版のインストール

### 5.1 事前準備

1. **MT5 をインストール**して口座にログインし、[ツール] → [オプション] → [エキスパートアドバイザ] で「アルゴリズム取引を許可する」にチェックを入れます。
2. ツールバーの **[アルゴリズム取引]** ボタンを ON にします。
3. **Python 3.13（64 ビット）**を https://www.python.org/ からインストールします（インストーラーで「py launcher」と「Add python.exe to PATH」にチェックを入れてください）。他の版では `setup_windows.bat` がエラーで止まります（テスト済みの組み合わせで動かすため）。

### 5.2 セットアップ

1. zip ファイルを任意の場所（例：`C:\GreatestTrader`）に展開します。
2. `GreatestTrader\python\setup_windows.bat` をダブルクリックします。
   - Python 3.13 の仮想環境 `.venv` が作られ、`requirements-lock.txt` に固定したテスト済みの版のパッケージ（MetaTrader5, numpy, pandas, PyYAML）と、グラフ・テスト用の matplotlib, pytest が入ります。
3. （任意）動作確認として、コマンドプロンプトで次を実行します。
   ```
   cd C:\GreatestTrader\python
   .venv\Scripts\activate
   python -m pytest
   ```
   「142 passed」と表示されれば正常です。

## 6. 設定ファイル（config.yaml）

`python\config\config.yaml` をメモ帳などで編集します（文字コード UTF-8 のまま保存してください）。

### 6.1 最低限の設定

```yaml
account:
  login:           # 空欄 = 起動中の MT5 にログイン済みの口座を使う（推奨）
broker:
  symbol_suffix: ""          # シンボル名の接尾辞（例 ".raw"）
  server_time_mode: auto     # 通常は auto のまま
  commission_per_lot: 7.0    # ★ECN 口座の 1 ロット往復手数料（口座通貨）。JPY 口座なら例 700
preset: stable5              # リスク設定のプリセット（stable5 / stable4 / safe2 / classic_*）
risk:                        # 本番の最初はプリセットのリスクを半分にする（9.3 節）
  risk_nr: 0.0175            #   stable5 の 0.035 の半分
  risk_es: 0.00875           #   stable5 の 0.0175 の半分
engine:
  dry_run: true              # 最初は true（注文を出さない）
```

### 6.2 プリセット

`preset:` の 1 行で、リスク管理の設定一式を切り替えます。コマンドで `--preset safe2` のように指定することもできます（`config.yaml` の `preset:` の行より優先）。ただし `config.yaml` の `risk:` に書いた上書きは、`--preset` を指定してもそのまま適用されます（その場合はログとバックテストの表示に「+ config.yaml risk overrides (…)」と出ます）。

| プリセット | 中核 4 ペアの 1 取引リスク | その他 10 ペア | 主な保護機能 | 必要なレバレッジの目安 |
|---|---|---|---|---|
| **stable5（既定）** | 3.5% | 0.875% | 合計リスク 8.75%、月次 −3% で全決済、日次 −1% で新規停止、DD 連動縮小（DD 5% でリスク半分） | 100 倍以上 |
| stable4 | 2.0% | 0.875% | 合計リスク 6%、月次 −3% で全決済、ほか stable5 と同じ | 50 倍以上 |
| safe2 | 1.0% | 0.5% | 合計リスク 2%、月次 −1% で新規停止・−1.5% で全決済、日次 −1% で新規停止 | 25 倍で可 |
| classic_conservative / classic_standard / classic_aggressive | 0.5% / 1.0% / 1.5%（全ペア同じ） | 同じ | v1.0 と同じ（DD 連動縮小 30%、日次 −5%） | 30 / 60 / 90 倍 |

- 中核 4 ペア：GBPCAD, EURCAD, AUDCAD, GBPCHF。その他 10 ペア：EURJPY, GBPJPY, USDJPY, GBPUSD, EURGBP, USDCHF, EURUSD, EURAUD, CHFJPY, GBPAUD。
- すべてのプリセットで、年末年始（12 月 20 日〜1 月 5 日、マーケット時間）は新規エントリーしません。
- `config.yaml` の `risk:` に書いた項目は、プリセットより優先されます。書かなかった項目はプリセットの値のままです。
- 6.1 節の「リスク半分」の例（`risk_nr: 0.0175` など）は **stable5 用の値**です。プリセットを変えるときは、そのプリセットの値の半分に書き換えてください（stable4：`risk_nr: 0.01`・`risk_es: 0.005`、safe2：`risk_nr: 0.005`・`risk_es: 0.0025`）。classic_* では `risk_nr`・`risk_es` は使われません（`profile` で決まるため）。
- プリセットの中身は `python\greatest_trader\presets\*.yaml` で確認できます。選び方の詳細は [05_安定化改修報告書.md](05_安定化改修報告書.md) の 7 章を参照してください。

### 6.3 主な設定項目

| セクション | 項目 | 説明 |
|---|---|---|
| account | login / password / server | 空欄ならログイン中の口座を使う。指定すると自動ログイン |
| account | terminal_path | MT5 が複数ある場合に `terminal64.exe` のパスを指定 |
| broker | symbol_suffix | 例 `.raw`、`-STD`、`m` |
| broker | symbol_map | 個別の名前変換。例 `{"EURUSD": "EURUSDmicro"}` |
| broker | server_time_mode | `auto`（推奨。稼働中ずっと自動判定し、確認できるまで新規エントリーしない）／ `ny7` ／ `fixed`（どちらも常時検証し、3 回続けて食い違うと新規エントリーを止めて通知） |
| broker | server_gmt_offset | `fixed` のときのオフセット（例：GMT+9 なら 9） |
| broker | commission_per_lot | 1 ロット往復の手数料（口座通貨）。**スプレッドのみの口座は 0** |
| （先頭） | preset | リスク設定のプリセット（6.2 節） |
| risk | risk_nr / risk_es | 1 取引のリスク（0.035 = 3.5%）。プリセットの値を上書きするときだけ書く |
| risk | symbol_risk_mult | 通貨ペア別のリスク倍率。書くと表全体が置き換わる（書かなかったペアは 1.0 倍）ため、変更するときはプリセットの 10 ペアをすべて書く |
| risk | max_total_risk | 合計リスク上限（0.0875 = 8.75%、0 = なし） |
| risk | max_same_direction_per_currency | 同じ通貨を同じ方向に賭けるポジションの上限（2 を推奨。1 にすると利益が大きく減る） |
| risk | max_open_positions | 同時保有上限 |
| risk | daily_loss_limit | 日次損失制限：その日の新規エントリーを停止（0.01 = 1%） |
| risk | monthly_loss_limit / monthly_hard_stop | 月次損失制限（新規停止）／月次ハードストップ（全決済して当月停止） |
| risk | dd_scale_full / dd_scale_floor | DD 連動のリスク縮小（倍率 = max(下限, 1 − DD ÷ 基準)） |
| risk | blackout_start / blackout_end | 年末年始の新規停止（"12-20" / "01-05"。空欄 "" で無効） |
| risk | max_drawdown_halt | 最大 DD で全新規エントリーを停止（stable5・stable4・safe2 は 0.20 = 20%、classic_* は 0.40） |
| risk | max_lots_per_order | 1 注文の最大ロット（既定 20、0 = なし）。深夜の薄い流動性で注文が市場を動かさないための上限 |
| risk | max_risk_amount | 1 取引の最大リスク額＝損切り時の損失額（口座通貨、既定 0 = なし）。例：円口座で 300000 |
| night_reversion | symbols | 対象通貨ペア。外すペアは削除する |
| night_reversion | atr_cost_mult | コストの高い口座は 2.5〜3.0 |
| euro_session | enabled | false にすると ES を停止 |
| notify | discord_webhook など | 通知先（任意） |
| notify | healthcheck_url | 死活監視（任意）。例：healthchecks.io の Ping URL。正常なら 5 分ごとにアクセスし、止まると外部サービスから連絡が来る |
| monitor | dd_alert | DD 警告（既定 0.15 = 15%。通知のみ） |
| monitor | daily_summary | 毎日のサマリー通知（既定 true） |
| monitor | edge_window_trades | 優位性モニターの対象取引数（既定 250） |
| monitor | stale_feed_minutes | 価格の更新が止まったときの通知（既定 10 分） |
| engine | dry_run | true = 注文を出さない |
| engine | state_file / log_dir / journal_dir | 状態ファイル・ログ・取引記録の場所（通常は変更不要） |
| backtest | account_currency / leverage | バックテストの口座通貨（ロット上限の換算に使用）と、口座レバレッジ（指定すると証拠金チェックを行う） |

## 7. Python 本稼働版の使い方

| バッチファイル | 内容 |
|---|---|
| `1_check.bat` | 接続確認（口座・シンボル・スプレッド・サーバー時間）。**売買はしない** |
| `2_run_dryrun.bat` | ドライラン。シグナルをログに記録するだけで**注文は出さない** |
| `3_run_live.bat` | **本番稼働**。実際に発注する。異常終了したとき、または MT5 と 30 分以上通信できないときは 30 秒後に自動で再起動する（起動・終了は `logs\restarts.log` に記録）。意図的な停止（二重起動・ネッティング口座など、終了コード 10）では再起動しない |
| `4_download_data.bat` | MT5 から過去 5 年分の M15 データを取得する |
| `5_backtest.bat` | Python でバックテストを実行する |
| `6_report.bat` | 本番の成績レポート（MT5 の口座履歴から、入出金を除いた月次成績・戦略別損益・3/6/12 か月成績・優位性モニター）を `backtest_output\live_report\` に出力する |
| `7_reset_halt.bat` | 最大 DD 停止を解除する（本番のエンジンを止めてから実行。最高資産・入出金・時計などの記録は残る） |

### 7.1 接続確認

`1_check.bat` を実行すると、次のような表示が出ます。

```
account equity : 10000.00 USD
symbol   broker         digits spread(p)  min lot   step
EURJPY   EURJPY              3      0.90     0.01   0.01
...
server time 2026-01-14 10:00:03  UTC 2026-01-14 08:00:03  -> detected mode=ny7 offset=+2.0h
```

- すべてのシンボルが表示されることを確認してください（ERROR が出る場合は `symbol_suffix` を見直します）。
- サーバー時間の判定は、市場が開いている平日に実行してください。本番稼働中は、エンジンが自動で常に確認します（起動直後は、新しいティックで確認できるまで新規エントリーを行いません。ログに `server clock verified` と出れば確認済みです）。

### 7.2 ドライラン

`2_run_dryrun.bat` を実行して、数日間動かします。日本時間の早朝（冬 07:00〜09:00、夏 06:00〜08:00）に、次のようなログが出れば正常です。

```
[DRY-RUN] would open NR SELL GBPCAD lots=0.17 entry~1.71245 SL=1.71530 TP=1.71160 risk=1.75% ...
```

### 7.3 本番稼働

1. まずデモ口座で `3_run_live.bat` を実行し、2〜4 週間、発注・TP 更新・時間決済が正しく動くことを確認します。
2. 本番口座に切り替え、**プリセットのリスクを半分にして**始めます（6.1 節の例、9.3 節）。
3. ウィンドウを閉じると停止します。MT5 のターミナルは常に起動し、ログインしたままにしてください。

### 7.4 24 時間・長期稼働の設定（VPS）

| 項目 | 設定 |
|---|---|
| 自動起動 | Windows の自動ログオン（Sysinternals Autologon など）を設定し、タスクスケジューラで「ログオン時」に MT5 と `3_run_live.bat` を起動します。スタートアップフォルダだけでは、Windows Update の再起動後に誰かがログオンするまで動きません |
| MT5 | [ツール] → [オプション] でログイン情報を保存。`config.yaml` の `account.terminal_path` に `terminal64.exe` のパスを書いておくと、ターミナルが閉じても再接続時に起動し直せます |
| リモートデスクトップ | 終了するときは「切断」（ウィンドウの × で閉じる）。**サインアウトしない**（MT5 とエンジンも終了します） |
| Windows Update | アクティブ時間を設定し、再起動は週末に行われるようにします（再起動後は自動で復帰します） |
| 時計 | 「時刻を自動的に設定する」を ON（サーバー時間の自動判定は PC の時計を基準にします） |
| 通知と死活監視 | Discord / Slack / Telegram のいずれかと、`notify.healthcheck_url`（任意）を設定します。毎日のサマリーが届かない、または死活監視から連絡が来たら、VPS・MT5・エンジンを確認します |
| コマンド画面 | 画面をクリックしても処理は止まりません（簡易編集モードを自動で無効化します） |

自動で処理されること：MT5 ターミナルの再接続、使えなくなった通貨ペアの除外（他のペアは取引を継続）、通知先が応答しないときの待ち（取引は止めない）、状態ファイルの毎日のバックアップ（14 世代）と、壊れたときのバックアップからの復元。

### 7.5 停止と再開

- 停止：ウィンドウを閉じる（または Ctrl+C）。保有中のポジションには SL・TP が付いたまま残ります。
- 再開：もう一度起動すれば、ブローカー側のポジション情報から自動で管理を再開します。
- **月次ハードストップ・日次の停止**は、翌月・翌日（マーケット時間）になると自動で解除されます。操作は不要です。
- **最大 DD で停止した場合の解除**（stable5 では最高資産から −20%。通常の運用では到達しない水準です）：原因（相場の急変・約定の異常・ブローカーの問題など）を確認してから、本番のエンジンを止めて `7_reset_halt.bat` を実行し、再起動します。停止だけが解除され、最高資産・入出金・時計などの記録は残ります。DD の記録もやり直す場合は、バッチファイルの `reset-halt` の行に `--rebase-peak` を付けます。MQL5 版は 4.5 節の InpResetHalt を使います。**状態ファイル（state.json）を削除しないでください**（DD・入出金の記録が消え、口座の照合もやり直しになります）。
- **入金・出金をしたとき**：自動で処理されます。MT5 の口座履歴から入出金を検出し、最高資産と日次・月次の基準を同じ比率で調整するため、出金が「損失」とみなされることはありません（ログと通知に `CASH FLOW` と表示されます）。念のため、取引時間外（日本時間の昼間など）に行ってください。
- **別の口座でログインしたとき**：状態ファイルは口座番号を記録しており、違う口座では取引しません（元の口座に戻すと自動で再開します）。別の口座で運用するときは、別のフォルダに展開して使ってください。

## 8. Python でのバックテスト

1. `4_download_data.bat` で MT5 から M15 データを取得します（`python\data\{通貨ペア}_M15.csv`）。
   - 取得できる期間はブローカーによって異なります。[ツール] → [オプション] → [チャート] の「チャートの最大バー数」を「Unlimited」にすると、多くの期間を取得できます。
2. `5_backtest.bat` を実行します（`config.yaml` の `preset:` の設定で計算します）。別のプリセットで試すときは、コマンドプロンプトで `python main.py backtest --preset safe2 --out backtest_output_safe2` のように実行します。

|---|---|
| summary.txt | 成績の要約（月利の複利換算・単純平均・中央値、CAGR、最大 DD〈決済ベース／含み損益込み〉など）、年利（各年）の表、月利表、戦略・通貨ペア別の成績 |
| trades.csv | 全取引の明細（決済理由に `month stop`〈月次ハードストップ〉なども記録。ロット数、上限前のロット数、想定元本、リスク額も記録） |

| monthly_returns.csv | 月利表（年 × 月、年間） |

| equity_curve.png | 資産曲線とドローダウンのグラフ |

- MT5 の「バーをエクスポート」で保存した CSV（`<DATE> <TIME> ...` 形式）も、`EURUSD_M15.csv` のような名前で `data` フォルダに置けば読み込めます。
- 期間を絞るときは、config.yaml の `backtest.start` / `backtest.end` を設定します。
- バックテストも本番と同じく 1 注文 20 ロットの上限を入れて計算します（`backtest.account_currency` の通貨に換算。円口座なら `JPY`、`initial_equity` も円で指定）。上限なしの理論値を見るときは `risk:` に `max_lots_per_order: 0` を書きます。

## 9. 運用ガイド

### 9.1 日々の確認（1 日 1 回、5 分）

- 毎日の `DAILY` サマリー通知が届いていること（資産・DD・月初来の成績・取引数・停止状態）。届かない場合は VPS・MT5・エンジンを確認します
- ログ（`python\logs\live_YYYY-MM-DD.log`）に `ERROR`（`order failed` / `close failed` など）や `HALT`・`NEW ENTRIES BLOCKED`（時計の不一致）・`unavailable`（使えなくなった通貨ペア）がないこと（`MONTH STOP` / `DAY STOP` は保護機能が働いた記録で、異常ではありません）
- 毎時の `heartbeat` 行が出ていること（エンジンが動いている証拠）
- 取引の記録は `python\journal\trades_YYYY.csv` に残ります（削除されません）

### 9.2 月次の確認

| 確認項目 | 判断 |
|---|---|
| 月間成績（`6_report.bat`） | マイナスの月は約 3 割の確率で起こる（想定内）。stable5・stable4 では −3% 前後で止まる月が年に 1〜2 回ある。12 か月の成績が −1.6% を下回ったら注意、−8.4%（過去最悪）を下回ったら再検証 |
| 優位性モニター | 月末に `EDGE WARN`（直近 250 取引の R の加重平均がマイナス）が出たら様子を見る。2 か月続いて `EDGE REVIEW` が出たら、実際のコストと最新データでの成績を確認する（[06_長期運用評価報告書.md](06_長期運用評価報告書.md) 7.1 節・8 章） |
| 取引回数 | 4.4 節の目安と比べる。極端に少ない場合はスプレッドが拡大している |
| 平均コスト | 想定より高ければ、`atr_cost_mult` を上げるか口座を見直す |
| ドローダウン | DD 警告（15%）が出たら原因を確認する。過去の最大は約 12% で、15% を超えるのは 10 年に 1% 未満の水準 |

### 9.3 リスクの上げ方

```
選んだプリセットのリスクを半分にして 2〜3 か月運用（6.1 節の例）
  ・実際のコスト（スプレッド＋手数料＋滑り）が検証の想定に近いことを確認
  ・取引回数・勝率が想定どおりであることを確認
  ↓
プリセットの値に戻す（risk: の上書きを消す）
```

- 最初から最大のリスクで始めないでください。検証では、運用開始直後の 1 か月目（2007 年 1 月）が全期間で最も悪い月の一つになる設定が多くありました。
- 中核 4 ペア（GBPCAD・EURCAD・AUDCAD・GBPCHF）は、2019 年 7 月以降のデータで検証できていません。MT5 ストラテジーテスターで、ご自身のブローカーの最新データを確認してから本来のリスクに戻してください。

### 9.4 ドローダウン時の自動の動き

stable5 の場合（他のプリセットの値は 6.2 節）：

- DD に応じてリスクが自動的に縮小します（DD 5% でリスク半分、DD 9% 以上で最小の 10%）。
- 1 日で −1% になると、その日の新規エントリーを停止します。
- 1 か月で −3% になると、**全ポジションを決済**し、その月は新規エントリーしません（翌月に自動で再開）。急変動のときは −3% を超えて止まることがあります。
- 年末年始（12 月 20 日〜1 月 5 日）は新規エントリーしません。
- 最高資産から −15% で警告を通知します（取引は変えません）。
- 最高資産から −20% で全新規エントリーを停止します（保有中のポジションは通常どおり決済。解除は `7_reset_halt.bat`、7.5 節）。
- 資産が最高値を更新しない期間が 2 年以上続くこともあります（2011 年 12 月〜2015 年 3 月の 1,176 日）。DD 連動の縮小でリスクが小さくなっている間は、回復にも時間がかかります。

### 9.5 長期運用の手順

毎日・毎月・四半期・年 1 回の確認内容と判断の目安は、[06_長期運用評価報告書.md](06_長期運用評価報告書.md) の 8 章にまとめています。特に、**年に 1 回（年末年始の新規停止期間に）、最新データで再検証**してください。

## 10. トラブルシューティング・FAQ

| 症状 | 原因と対処 |
|---|---|
| `MT5 initialize failed` | MT5 が起動していない／ログインしていない。`terminal_path` の指定、または MT5 の再起動を試す。稼働中に MT5 が再起動した場合は自動で再接続する（30 分以上回復しないと `CRITICAL` を通知してエンジンを再起動） |
| `server clock not verified yet` / `NEW ENTRIES BLOCKED: broker clock mismatch` | サーバー時間を確認中、または設定と食い違っている。市場が開いている平日なら数分で確認される。食い違いが続く場合は `server_time_mode: auto` にし、PC の時計が正確か確認する |
| `another GreatestTrader process already uses state.json` | 本番エンジンを 2 つ起動しようとした。1 つだけにする |
| `this MT5 account uses NETTING` | ネッティング口座。ヘッジング口座を用意する |
| `terminal is logged into account …, but the state belongs to account …` | MT5 が別の口座にログインしている。元の口座に戻すと再開する |
| `lot cap: intended X lots, sending 20` | 1 注文 20 ロットの上限が効いた（口座が大きくなったため。異常ではない） |
| `symbol XXX unavailable: trading continues without it` | その通貨ペアが使えなくなった（名前の変更・非表示など）。他のペアは取引を継続。`symbol_suffix` / `symbol_map` や気配値表示を確認する |
| `symbol XXX not available` | シンボル名が異なる。`symbol_suffix` または `symbol_map` を設定する |
| `Algo trading is DISABLED` | MT5 ツールバーの [アルゴリズム取引] ボタンを ON にする |
| `retcode=10027` | MT5 側で自動売買が無効。上と同じ |
| `retcode=10019`（資金不足）や `skip (insufficient free margin)` | 証拠金不足。プリセットを下げる（stable5 → stable4 → safe2）か、`max_total_risk` / `max_open_positions` を下げる |
| `retcode=10030`（Unsupported filling） | 自動で別の執行方式を試す。続く場合はブローカーに確認する |
| シグナルが全く出ない | スプレッドが広い（コストフィルターで見送られている）。`1_check.bat` でスプレッドを確認する |
| 取引時刻がずれている | `server_time_mode: auto`（既定）なら自動で検出して新規エントリーを止めます。PC の時計（自動設定）と、ログの `server clock` の行を確認する |
| EA のコンパイルエラー | MT5 を最新ビルドに更新する。`Trade\Trade.mqh` が標準で入っていることを確認する |
| テスターで NR シンボル数が少ない | 気配値表示に該当シンボルがない、または接尾辞が未設定 |
| Python と EA の両方で約定した | 同じ口座で両方を動かしている。どちらか一方にする |

**Q. 月利 5% は本当に達成できますか？**
A. 口座が小さいうち（約 6.6 万ドル＝約 1,000 万円まで）の過去の検証では、stable5 の複利換算の月利は 2007〜2022 年で 5.38%、2017〜2022 年で 5.33% でした。一方、2011〜2022 年は 4.22% で 5% に届いていません。中央値（典型的な月）は 2.4% で、一部の大きく勝った月が平均を押し上げています。コストが 0.5 pips 高いと 3.50% に、中核ペアを後知恵なしで選ぶと 4.70% に下がります。10 年の模擬運用の中央値は、データの期間によって 3.8〜5.1% です。また、口座が大きくなると 1 注文 20 ロットの上限により利益は金額で頭打ちになり、月利（%）は下がります（1 万ドルから 15 年の通算で 3.07%）。本番の現実的な期待値は月利 3% 前後と考えてください。詳しくは [05_安定化改修報告書.md](05_安定化改修報告書.md) と [06_長期運用評価報告書.md](06_長期運用評価報告書.md) を参照してください。将来の成績は保証できません。

**Q. ドローダウン 20% 以内、最悪月 −2% 程度にできますか？**
A. DD 20% 以内は stable5・stable4・safe2 のいずれも過去検証で満たしています（約 11〜12%。コストや損切りの滑りを厳しくしたストレステストでも 19% 以内）。最悪月 −2% 程度を満たすのは safe2 だけで、その場合の月利は 2% 程度です。月利 5% と最悪月 −2% を両立する設定は見つかりませんでした（[05_安定化改修報告書.md](05_安定化改修報告書.md) 3.3 節）。

**Q. 月の途中で全ポジションが決済され、取引が止まりました。**
A. 月次ハードストップ（stable5 では月初から −3%）が働いています。ログに `MONTH STOP` と記録されます。翌月 1 日（マーケット時間）に自動で再開します。

**Q. 通貨ペアを減らしてもよいですか？**
A. 可能ですが、分散効果が下がり、月ごとの成績のばらつきが大きくなります。コストが高いペア（GBPAUD・GBPCAD など）を外す場合は、`symbols` から削除してください。

**Q. パラメータを最適化してもよいですか？**
A. 推奨しません。既定値は、期間ごとの検証で安定していた領域の中心です。ピークを狙った最適化は将来の成績を悪化させやすくなります。
